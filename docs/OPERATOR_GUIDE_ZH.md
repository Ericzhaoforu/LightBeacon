# LightBeacon 首次使用与现场操作手册

本文面向第一次接触 LightBeacon 的现场操作人员。正常使用不需要修改程序、重新编译固件或打开 ESP-IDF；操作人员只需要完成接线检查、配网、启动主机控制服务和使用网页控制台。

> 适用硬件：ESP32-WROOM-32UE、288 颗 WS2812B 侧边灯带、64 颗 WS2812B 顶部点阵/第二路灯带、Adafruit Pixel Shifter 6066、12 V 磷酸铁锂电池和 12 V→5 V DC-DC。

## 1. 开始前准备

现场应随设备交付以下信息。密码和密钥不要写入公开文档、聊天记录或仓库。

| 项目 | 由交付人员填写 |
|---|---|
| 现场 2.4 GHz Wi-Fi SSID | ____________________ |
| 现场 Wi-Fi 密码 | ____________________ |
| 控制台管理员密码 | ____________________ |
| 节点临时配网热点密码 | ____________________ |
| 64 位十六进制 HMAC 控制密钥 | 单独安全交付 |
| 节点 ID 清单 | ____________________ |
| 控制电脑/项目目录 | ____________________ |

还需要：

- 已配置好的 Windows 或 Linux 控制电脑；
- 专用 2.4 GHz AP/路由器；
- 手机或电脑，用于第一次给节点配网；
- 万用表，用于首次通电前确认 DC-DC 输出；
- 小一字螺丝刀，用于 6066 模块端子；
- 与实际电流匹配的保险、线材、接插件和电源分配端子。

## 2. 系统组成

一个 LightBeacon 节点包括：

1. 12 V 磷酸铁锂电池，带 BMS；常见 4 串电池标称约 12.8 V，充满可能达到约 14.6 V。
2. 输入范围覆盖电池最高电压的 DC-DC 降压模块，输出调至稳定 5.0 V。
3. ESP32-WROOM-32UE 开发板和外置 2.4 GHz 天线。
4. Adafruit Pixel Shifter 6066，两路 3.3 V→5 V 数据信号转换。
5. 两只约 330 Ω 数据串联电阻，每路一只。
6. 288 颗 WS2812B 侧边灯带，数据 GPIO18。
7. 64 颗 WS2812B 顶部点阵/第二路灯带，数据 GPIO19。
8. 5 V 电源分配、支路保险、侧带电源注入和输入电容。
9. 专用局域网 AP 和运行 LightBeacon 控制服务的电脑。

## 3. 电气安全

12 V 磷酸铁锂电池能够提供很大的短路电流。接线错误可能烧毁设备、导线或接插件。

- 电池正极附近必须设置总保险，之后再进入总开关和 DC-DC。
- 12 V 电池电压绝对不能直接接入 ESP32、6066 或 WS2812B。
- DC-DC 未接负载时，先用万用表把输出调到 5.0 V，再连接设备。
- DC-DC 的输入额定上限必须高于电池充满电压，输出电流和散热必须有余量。
- 352 颗 WS2812B 在全白故障工况下理论上可能接近 21.1 A@5 V。不要依赖固件的 25% 亮度限制代替保险、线径和散热设计。
- ESP32、6066、两路 LED 和 DC-DC 输出负极必须共地。
- 两路 LED 应分别设置支路保险；保险值按线径、接插件和实际电气设计确定。
- 288 颗侧带需要多点注入电源，注入时 `+5V` 和 `GND` 必须成对连接。
- 不要在系统带电时插拔 LED 数据线。
- 正常现场运行不需要 USB。若要把 ESP32 接入电脑 USB，最安全的做法是先关闭电池并断开 ESP32 外部 `5V/VIN`，避免外部 5 V 反灌电脑 USB。

## 4. 完整接线

### 4.1 电源和信号总图

```text
12 V 磷酸铁锂电池
  BAT+ ── 总保险 ── 总开关 ────────── DC-DC IN+
  BAT- ───────────────────────────── DC-DC IN-

DC-DC（先空载调到 5.0 V）
  OUT+ ──┬── ESP32 支路保险 ─────── ESP32 5V/VIN
         ├── 侧带支路保险 ───────── 侧带 +5V 注入点
         └── 顶部支路保险 ───────── 顶部点阵/灯带 +5V

  OUT- ── 公共 GND 母线 ──┬──────── ESP32 GND
                           ├──────── 6066 G
                           ├──────── 侧带 GND 注入点
                           └──────── 顶部点阵/灯带 GND

ESP32 与 Adafruit Pixel Shifter 6066
  ESP32 3V3    ───────────────────── 6066 V
  ESP32 GND    ───────────────────── 6066 G
  ESP32 GPIO18 ───────────────────── 6066 DAT
  6066 D5      ── 330 Ω ─────────── 侧带 DIN

  ESP32 GPIO19 ───────────────────── 6066 CLK
  6066 C5      ── 330 Ω ─────────── 顶部点阵/灯带 DIN

  6066 !D5     ───────────────────── 不连接
```

### 4.2 逐端子核对

| 起点 | 终点 | 用途/注意事项 |
|---|---|---|
| DC-DC `OUT+` | ESP32 `5V/VIN` | 只能接板上明确标注的 5V/VIN，不能接 3V3 |
| DC-DC `OUT-` | ESP32 `GND` | 公共地 |
| ESP32 `3V3` | 6066 `V` | 6066 的控制侧供电 |
| ESP32 `GND` | 6066 `G` | 同时与 DC-DC OUT- 共地 |
| ESP32 `GPIO18` | 6066 `DAT` | 侧带数据输入 |
| 6066 `D5` | 330 Ω → 侧带 `DIN` | 电阻无方向，靠近第一颗 LED |
| ESP32 `GPIO19` | 6066 `CLK` | 把第二个缓冲通道用作第二路 WS2812B 数据 |
| 6066 `C5` | 330 Ω → 顶部 `DIN` | 电阻无方向，靠近第一颗 LED |
| 6066 `!D5` | 不连接 | 它是反相信号，不能用于 WS2812B |
| DC-DC `OUT+` | 两路 LED `+5V` | 分支保险后供电，侧带多点注入 |
| DC-DC `OUT-` | 两路 LED `GND` | 与 ESP32、6066 共地 |

每路 LED 电源输入附近建议并联一只 470–1000 µF 电解电容：电容正极接 `+5V`，负极接 `GND`。电解电容有极性，禁止接反。

数据线必须进入灯带的 `DIN`，不能接 `DOUT`。灯带上的箭头应从控制器指向灯带末端。数据线旁边应有一根短而可靠的地线作为信号参考。

### 4.3 通电前检查

断开电池后逐项确认：

- 没有任何 12 V 线路接到 5 V 设备；
- DC-DC 极性正确，空载输出为 5.0 V；
- `+5V` 与 `GND` 不短路；
- ESP32 接的是 `5V/VIN`，不是 `3V3`；
- 6066 的 `V` 接 ESP32 `3V3`；
- GPIO18 经过 `DAT→D5→330 Ω` 到侧带 DIN；
- GPIO19 经过 `CLK→C5→330 Ω` 到顶部 DIN；
- `!D5` 悬空；
- 所有设备共地；
- 电解电容极性正确；
- 外置天线已经接好，并远离 DC-DC、金属遮挡和大电流电源线。

## 5. 局域网要求

LightBeacon 只需要局域网，不需要互联网。现场 AP 应满足：

- 开启 2.4 GHz Wi-Fi 和 DHCP；
- 关闭“客户端隔离/AP Isolation/Wireless Isolation”；
- 控制电脑和所有 ESP32 位于同一个二层局域网；
- 控制电脑尽量通过网线连接 AP；若使用 Wi-Fi，也必须连接同一个现场网络；
- Windows 防火墙只在该私有网络上允许 TCP 8080 和 UDP 40404；
- 现场有多个 AP 时使用有线回程，并保持同一局域网和关闭客户端隔离。

ESP32 使用 DHCP，通常不需要配置固定 IP。主机会通过 UDP 自动发现节点。

## 6. 节点配网

### 6.1 判断节点是否已经配过网

节点上电后始终先保持熄灭：

- **从未配网或配置被清除**：节点建立 `LightBeacon-XXXXXX` 临时热点。
- **已经配网**：节点直接尝试连接保存的现场 Wi-Fi，不再建立临时热点。

`XXXXXX` 是节点 MAC 地址末 6 位，用于区分多个待配节点。

### 6.2 第一次配网

配网前准备好现场 SSID、Wi-Fi 密码、该节点分配的唯一节点 ID，以及与主机 `.env` 完全一致的 64 位十六进制 HMAC 密钥。

1. 只给一个待配节点通电，等待约 10 秒。
2. 在手机或电脑 Wi-Fi 列表中连接 `LightBeacon-XXXXXX`。
3. 输入交付表中的“节点临时配网热点密码”。
4. 系统可能提示“此网络没有互联网”，这是正常现象；选择继续保持连接。
5. 暂时关闭 VPN、代理和手机的“自动切换到移动网络/更好的网络”功能。
6. 浏览器手动输入 `http://192.168.4.1/`。必须使用 `http`，不要改成 `https`。
7. 按下表填写页面。

| 字段 | 填写要求 |
|---|---|
| 节点 ID | 唯一，1–32 个字符，只能使用 `A-Z a-z 0-9 _ -`；换网时应继续使用原 ID |
| 现场 Wi-Fi SSID | 精确填写 2.4 GHz 网络名称，注意大小写和空格 |
| Wi-Fi 密码 | 精确填写；开放网络可以留空 |
| HMAC 密钥 | 64 个十六进制字符，必须与控制主机完全相同，不可临时自行生成 |
| 侧带灯珠数 | 当前硬件填写 `288` |
| 顶部灯珠数 | 当前硬件填写 `64` |
| 亮度安全上限 | 当前建议填写 `25` |

8. 点击“保存并重启”。
9. 配网热点随后消失是正常现象，表示节点正在重启并加入现场 Wi-Fi。
10. 如果使用控制电脑配网，把电脑重新连接到现场局域网。
11. 启动控制台后，节点通常会在数秒内显示在线。

如果提交后节点始终不在线，最常见原因是 SSID/密码错误、现场网络不是可用的 2.4 GHz 网络、客户端隔离未关闭，或 HMAC 密钥与主机不一致。

### 6.3 已配过网，但需要换到另一个局域网

当前固件没有单独“只修改 Wi-Fi”的入口。运行中长按 BOOT 会清除该节点的**全部 LightBeacon 应用配置**，包括节点 ID、Wi-Fi、HMAC 密钥、灯珠数量和亮度上限，然后重新进入配网模式。

1. 让 ESP32 正常上电并等待启动完成。
2. 在正常运行状态下按住 `BOOT` 按钮至少 5 秒，然后松开。
3. 不要一边按 BOOT 一边重新上电，否则可能进入固件下载模式。
4. 节点会自动重启；等待出现 `LightBeacon-XXXXXX` 热点。
5. 按“第一次配网”重新填写所有字段。
6. 节点 ID 应填写原来的 ID，除非交付人员明确要求更换。
7. HMAC 密钥仍应填写控制主机使用的同一密钥。

如果按错网络，可再次在节点正常运行时长按 BOOT 5 秒重新配置。

## 7. 启动现场控制台

控制电脑应由交付人员预先准备好 Python 环境、`.venv`、网页构建和本地 `.env`。普通操作人员不要修改 `.env`，也不要重新生成 HMAC 密钥。

### 7.1 Windows

1. 将电脑连接到 LightBeacon 现场局域网。
2. 打开 PowerShell，进入 LightBeacon 项目目录。
3. 运行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-host.ps1
   ```

4. 第一次启动如果 Windows 防火墙询问权限，只允许“专用网络/Private network”，不要向公共网络开放。
5. 保持该 PowerShell 窗口运行，不要关闭。
6. 浏览器打开 `http://127.0.0.1:8080/`。
7. 输入交付表中的控制台管理员密码；登录页面不需要用户名。

如果服务已经运行，直接刷新 `http://127.0.0.1:8080/` 即可。不要同时启动两个主机服务实例。

### 7.2 Linux

在已准备好的项目目录执行：

```sh
./scripts/run-host.sh
```

然后打开 `http://127.0.0.1:8080/`。

### 7.3 从现场其他电脑或平板访问

在控制主机防火墙已经允许 TCP 8080 的前提下，可打开：

```text
http://<控制主机的局域网IP>:8080/
```

该入口只应在封闭现场局域网内使用，不要把 8080 端口直接暴露到互联网。

这种方式中，原控制电脑仍然运行 LightBeacon 主机服务，其他电脑只作为浏览器客户端。浏览器客户端只需要控制台管理员密码，不需要安装程序、保存 HMAC 密钥或重新给 ESP32 配网。若不希望其他人接触系统级 HMAC 密钥，应优先采用这种方式。

### 7.4 把控制主机迁移到另一台电脑

只有当原控制电脑不再运行、另一台电脑需要直接和 ESP32 通信时，才属于“控制主机迁移”。新主机必须安装 LightBeacon 主机程序，并持有与现有 ESP32 完全相同的 HMAC 密钥。

#### 迁移前必须理解

- **同一局域网内只能运行一个 LightBeacon 主机服务。**两个主机会产生不同会话 ID，导致节点反复进入新会话并熄灭。
- 如果现场 Wi-Fi 不变，并且新主机使用原 HMAC 密钥，ESP32 不需要重新配网。
- 更换主机 IP 通常不影响基本控制；节点使用 DHCP 和 UDP 自动发现。
- `LIGHTBEACON_PUBLIC_BASE_URL` 应更新为新主机的局域网地址，尤其是需要 OTA 时。
- HMAC 密钥是系统级控制凭证。持有该密钥且能进入现场局域网的人，理论上能够生成节点认可的控制消息。
- 如果只需要让另一人操作灯效，不需要迁移主机；让其浏览器访问原主机即可。

#### 新主机需要准备的内容

由维护人员在新电脑上准备：

- LightBeacon 项目或经过验证的部署包；
- Python 3.12 和该电脑本地创建的 `.venv`；旧电脑的 `.venv` 不应直接复制到不同电脑；
- 已构建的网页静态文件；
- 新电脑本地的 `.env`；
- 可选的 `data/` 数据目录，用于保留二维布局和节点历史；
- Windows 专用网络上的 UDP 40404 和 TCP 8080 防火墙权限。

新主机 `.env` 中各秘密的处理方式：

| 配置 | 迁移要求 |
|---|---|
| `LIGHTBEACON_HMAC_KEY` | 必须与原主机和所有现有 ESP32 完全相同 |
| `LIGHTBEACON_SESSION_SECRET` | 可以重新生成；旧网页登录会话会失效 |
| `LIGHTBEACON_ADMIN_PASSWORD_HASH` | 可以保留，也可以由维护人员设置新管理员密码 |
| `LIGHTBEACON_PUBLIC_BASE_URL` | 改为新主机的现场局域网 IP 和 `:8080` |

不要通过普通聊天、公开网盘或代码仓库发送 `.env`。推荐由维护人员现场创建，或通过密码管理器、加密文件/加密 U 盘传递；传输完成后删除临时副本。

#### 通过 GitHub 迁移源码

可以把可提交的源码上传到 GitHub，另一台电脑再通过 `git clone` 或 `git pull` 获取。推荐使用私有仓库。不要理解成“除 `.env` 外的所有本地文件都上传”：应让项目根目录的 `.gitignore` 正常排除本地环境、生成文件和秘密。

以下内容不应上传：

- `.env`；
- `.venv/`；
- `data/` 和 `logs/`；
- `web/node_modules/` 和 `web/dist/`；
- `firmware/build/`、`firmware/sdkconfig`、`firmware/keys/`；
- 任何真实密码、HMAC 密钥、OTA 私钥或现场网络配置。

`.env.example` 应保留在 GitHub 中，因为它只包含字段说明和占位符。提交前至少执行：

```powershell
git check-ignore .env
git status --short
git ls-files .env
```

预期结果：第一条应显示 `.env` 被忽略，第三条不应输出任何内容。不要使用 `git add -f .env`。如果 `.env` 曾经被提交过，仅添加 `.gitignore` 不会删除 Git 历史中的秘密，应立即轮换密钥并清理仓库历史。

#### 新 Windows 主机：从 GitHub 安装

新电脑需要预先安装 Git、Python 3.12、Node.js/npm。以下命令只安装和构建程序，不需要修改源码：

```powershell
git clone <GitHub仓库地址> LightBeacon
cd LightBeacon

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .

cd web
npm ci
npm run build
cd ..
```

`pip install -e .` 会安装 FastAPI、Uvicorn 和主机所需的 Python 依赖。`npm ci` 和 `npm run build` 会依据仓库中的锁定文件生成 `web/dist/` 控制台页面。正常运行不需要安装 ESP-IDF，也不需要重新编译 ESP32 固件。

完成以上步骤后，通过安全渠道把原主机的 `.env` 放到新项目根目录。不要把 `.env` 放进 GitHub。然后根据新电脑现场网卡的 IPv4 地址修改：

```text
LIGHTBEACON_PUBLIC_BASE_URL=http://<新主机局域网IP>:8080
```

例如新电脑在 LightBeacon 局域网中的地址为 `192.168.50.30`：

```text
LIGHTBEACON_PUBLIC_BASE_URL=http://192.168.50.30:8080
```

修改该地址不需要重新配置 ESP32。它主要用于让节点在 OTA 时访问新主机；即使暂时不使用 OTA，也应填写新主机在现场局域网中可达的地址。建议在路由器中为控制主机设置 DHCP 地址保留，避免该地址变化。

复制原 `.env` 时，以下内容不要随意修改：

- `LIGHTBEACON_HMAC_KEY` 必须保持原值，否则现有节点不会认可新主机；
- HTTP 端口和 UDP 端口应继续使用 8080 和 40404，除非维护人员同步调整整个部署；
- `LIGHTBEACON_BIND_HOST` 应保持 `0.0.0.0`，使主机能够监听现场网络。

`LIGHTBEACON_SESSION_SECRET` 可以重新生成，管理员密码哈希也可以由维护人员更换，但这不是普通迁移的必需步骤。把完整 `.env` 交给对方，相当于授予其运行系统控制主机的权限，应只交给受信任人员。

最后启动服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-host.ps1
```

浏览器打开 `http://127.0.0.1:8080/`。

#### 新 Linux 主机：从 GitHub 安装

```sh
git clone <GitHub仓库地址> LightBeacon
cd LightBeacon

python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e .

```

Linux 同样需要把原 `.env` 通过安全渠道放到项目根目录，并修改 `LIGHTBEACON_PUBLIC_BASE_URL`。根据发行版防火墙配置，仅在现场私有网络允许 UDP 40404 和 TCP 8080。

#### 完整迁移步骤

1. 在原主机控制台点击“紧急全灭”，确认所有节点为 `OFF`。
2. 在原主机 PowerShell/终端中按 `Ctrl+C`，彻底停止旧主机服务。
3. 备份原项目目录和本地 `.env`。`.env` 只通过安全方式交给负责配置新电脑的维护人员。
4. 若需要保留布局和节点历史，在旧服务停止后复制 `data/` 目录；不复制也能发现和控制节点，但需要重新建立布局。
5. 在新电脑从 GitHub 克隆 LightBeacon，由维护人员按上面的命令创建 `.venv`、安装 Python 依赖并构建网页。
6. 在新电脑创建本地 `.env`：写入原 HMAC 密钥，设置会话密钥、管理员密码哈希和新主机局域网地址。
7. 将新电脑连接到节点所在的同一个局域网，确认 AP 客户端隔离已关闭。
8. 在新电脑防火墙上只为专用网络允许 UDP 40404 和 TCP 8080。
9. 确认原主机服务仍然关闭，然后在新主机运行 `scripts\run-host.ps1` 或 `scripts/run-host.sh`。
10. 打开新主机的 `http://127.0.0.1:8080/`，用新主机配置的管理员密码登录。
11. 等待节点自动出现；核对在线数量、节点 ID、MAC、RSSI 和是否存在 ID 冲突。
12. 如果复制了 `data/`，核对原二维布局；否则重新绑定布局并保存。
13. 只选一个节点，以 5% 亮度测试 `SOLID_BLUE`，然后发送 `OFF`。
14. 全部检查通过后再恢复现场操作，并安全删除迁移过程中产生的密钥临时副本。

#### 新主机发现不了节点

按以下顺序检查：

1. 原主机是否仍在运行；
2. 新主机与节点是否在同一局域网；
3. AP 客户端隔离是否关闭；
4. UDP 40404 是否被新主机防火墙阻止；
5. 新主机 `LIGHTBEACON_HMAC_KEY` 是否与节点完全一致；
6. 节点是否仍连接原来的现场 Wi-Fi。

HMAC 不一致时，网络数据包仍可能到达新主机，但主机和节点都会拒绝这些消息，因此控制台看起来像“没有节点”或命令始终无响应。

如果原主机上的 HMAC 密钥已经丢失，当前固件不会从 ESP32 配网页面回显密钥。此时只能生成新密钥、更新新主机 `.env`，并长按每个节点 BOOT 5 秒后使用新密钥重新配网全部节点。

### 7.5 主机启动时的安全行为

每次启动主机服务都会建立新的控制会话，并立即发送全灭命令。布局和节点历史会保留，但上次灯效不会自动恢复。这是设计行为，不是故障。

## 8. 使用控制台

### 8.1 确认节点状态

登录后先检查页面顶部：

- “实时连接”表示浏览器与主机服务连接正常；
- 在线数量应与已通电节点数量一致；
- 节点显示 RSSI、实际亮度和当前灯效；
- 节点约 5 秒无状态上报会被标记为离线；
- 如果出现“ID 冲突”，说明两个 MAC 使用了同一节点 ID。系统会阻止向该 ID 发送非 OFF 命令，必须重新给其中一个节点配唯一 ID。

### 8.2 第一次设置二维布局

1. 点击“编辑布局”。
2. 设置现场行数和列数。
3. 在每个格子中选择对应节点 ID；空位置可以保持未绑定。
4. 一个节点 ID 不能绑定到两个格子。
5. 点击“保存布局”。

布局保存到主机 SQLite 数据库，主机重启后仍会保留。

### 8.3 选择节点

- 单击格子选择一个节点；
- 按住鼠标拖动可框选多个格子；
- 点击“全选已绑定”选择全部已绑定节点；
- 点击“清除选择”取消选择。

发送命令前，页面会显示当前选中了多少个已绑定节点。

### 8.4 设置灯效

系统提供以下固定模式：

| 模式 | 效果 | 需要设置频率 |
|---|---|---|
| `OFF` | 熄灭 | 否 |
| `BLINK_RED` | 红色闪烁 | 是 |
| `BLINK_GREEN` | 绿色闪烁 | 是 |
| `BLINK_BLUE` | 蓝色闪烁 | 是 |
| `SOLID_BLUE` | 蓝色常亮 | 否 |

操作步骤：

1. 选择一个或多个已绑定节点。
2. 选择灯效模式。
3. 闪烁模式设置频率，范围 `0.1–5.0 Hz`，占空比固定为 50%。
4. 设置请求亮度，范围 `1–100%`。
5. 点击“应用到 N 个节点”。
6. 查看页面底部的命令结果；成功节点应显示 `accepted` 或成功数量。

节点实际亮度不会超过配网时设置的安全上限。默认上限为 25%，例如请求 80%，实际仍为 25%。

第一次点亮建议：

1. 只选择一个节点；
2. 亮度设置为 5%；
3. 先发送 `SOLID_BLUE`；
4. 检查两路 LED、颜色、供电和是否闪烁异常；
5. 发送 `OFF`；
6. 再测试 1.0 Hz 的红、绿、蓝闪烁。

### 8.5 紧急全灭

页面顶部始终有“紧急全灭”按钮。发现错误选择、灯效异常、人员接近设备、电源过热或任何不确定情况时，立即点击该按钮。

紧急全灭会广播发送三次，并不依赖有效时间同步。之后仍应观察页面状态，必要时关闭电池总开关。

### 8.6 失联保护

- 节点连续约 5 秒收不到合法主机心跳会自动熄灭。
- Wi-Fi 恢复后节点不会自动恢复旧灯效，必须由当前主机会话重新发送命令。
- ESP32 重启、主机重启、Wi-Fi 断开和 OTA 开始时都会保持熄灭。

## 9. 建议的现场操作顺序

### 开机

1. 检查电池、DC-DC、保险、接插件、天线和 LED 线缆。
2. 启动现场 AP，确认 2.4 GHz 网络可用。
3. 启动控制电脑并接入现场局域网。
4. 打开电池总开关，节点上电；此时灯默认保持熄灭。
5. 启动 LightBeacon 主机服务。
6. 登录控制台，确认在线节点数量、ID 和 RSSI。
7. 点击一次“紧急全灭”，建立明确的安全初始状态。
8. 选择目标节点并下发灯效。

### 关机

1. 在控制台点击“紧急全灭”。
2. 确认节点显示 `OFF`。
3. 在主机 PowerShell/终端中按 `Ctrl+C` 停止服务。
4. 关闭电池总开关，确认两路 LED 和 ESP32 均断电。
5. 最后关闭 AP 和控制电脑。

## 10. 常见故障排查

| 现象 | 优先检查 |
|---|---|
| 打不开 `127.0.0.1:8080` | 主机脚本是否正在运行；是否误关 PowerShell；8080 是否被其他程序占用 |
| 控制台能打开但节点为 0 | 控制电脑和节点是否在同一局域网；客户端隔离；UDP 40404 防火墙；节点是否已正确配网 |
| 找不到 `LightBeacon-XXXXXX` | 节点可能已经配过网；正常上电后长按 BOOT 5 秒清除配置；检查 ESP32 供电 |
| 手机连上配网热点但打不开页面 | 保持连接无互联网热点；关闭 VPN/代理/自动切网；手动输入 `http://192.168.4.1/` |
| 提交配置后热点消失 | 正常现象；节点正在重启并连接现场网络 |
| 提交配置后节点不出现 | SSID/密码错误；非 2.4 GHz；客户端隔离；HMAC 不一致；主机服务未启动 |
| 节点显示 ID 冲突 | 两个节点用了同一 ID；长按其中一个 BOOT 5 秒并重新设置唯一 ID |
| 命令 timeout/ACK 失败 | RSSI 太低、丢包、主机防火墙、节点离线或局域网隔离 |
| LED 完全不亮 | 5 V 电源、支路保险、共地、DIN/DOUT 方向、D5/C5 接线、330 Ω、电源极性、是否选择节点 |
| 只有一路 LED 亮 | 检查 GPIO18→DAT→D5 和 GPIO19→CLK→C5 两条独立路径；`!D5` 不能使用 |
| LED 花灯或随机闪烁 | DC-DC 压降、注入不足、地线不可靠、数据线过长、缺少 330 Ω、电平转换器接错、DC-DC 干扰 |
| 点亮时 ESP32 重启 | DC-DC 瞬时压降、线径不足、接头压降、共地布局不良或输入电容不足 |
| 红绿颜色对调 | 检查灯带型号/颜色顺序；当前固件按 GRB 配置，联系维护人员，不要现场改程序 |
| 主机重启后灯全灭 | 正常安全行为；重新选择节点并发送新灯效 |

现场覆盖目标是节点 RSSI 约 `-75 dBm` 或更好。RSSI 更差、频繁离线或命令重试时，优先移动 AP/天线、远离金属和 DC-DC 大电流回路，必要时增加有线回程 AP。

## 11. 操作人员不要修改的内容

以下操作留给维护人员：

- 修改或提交 `.env`；
- 更换 HMAC 控制密钥；
- 修改管理员密码哈希；
- 改 GPIO、灯珠数量默认值或协议端口；
- 重新编译、烧录 ESP32 固件；
- 执行 OTA；
- 修改保险值、线径、电源注入或 DC-DC 额定设计。

需要更换现场 Wi-Fi 时，操作人员只需按照第 6.3 节重新配网，不需要改程序。需要把系统移到一台全新的控制电脑时，应由维护人员安装运行环境并安全迁移 `.env` 和数据库。

## 12. 现场快速检查表

开机前：

- [ ] 电池/BMS、总保险和总开关正常
- [ ] DC-DC 输出确认是 5.0 V
- [ ] 三个 5 V 支路极性正确且保险有效
- [ ] ESP32、6066、两路 LED 共地
- [ ] 6066 V 接 ESP32 3V3
- [ ] GPIO18→DAT→D5→330 Ω→侧带 DIN
- [ ] GPIO19→CLK→C5→330 Ω→顶部 DIN
- [ ] 天线连接且远离金属、DC-DC 和大电流线
- [ ] AP 已开启 2.4 GHz、DHCP，客户端隔离已关闭

控制前：

- [ ] 主机服务正在运行
- [ ] 浏览器显示“实时连接”
- [ ] 在线节点数量正确，无 ID 冲突
- [ ] 布局绑定正确，目标选择正确
- [ ] 首次测试亮度 5%

结束时：

- [ ] 已执行紧急全灭并确认 OFF
- [ ] 已用 Ctrl+C 停止主机服务
- [ ] 已关闭电池总开关
